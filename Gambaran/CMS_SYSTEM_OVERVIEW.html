2Siklus transaksi container

Alur kerja CT

Tiap transaksi: DRAFT → POST → APPROVE
1
Aktivitas Harian
Turun / Naik CT, Putus Gerbong, CT-DT, Truck Unloading, Uplift / Unloading → status CT otomatis berubah saat POST
2
Inspeksi
Hanya CT berstatus O. POST → CT jadi TSO / TSOI. Approve wajib isi jenis perbaikan + root cause
3
BAST ke Vendor (BAST 1)
Maintenance atau Upgrade & Repair, item & harga dari kontrak. Approve 3 tingkat
4
Progress Perbaikan
% progress per CT dari vendor; tidak bisa approve jika ada progress lama (vendor + lokasi sama) belum disetujui
5
BAST dari Vendor (BAST 2)
Approve → garansi dihitung dari kontrak, BAST 1 ditandai selesai, CT kembali SO
6
Scrap
Dokumen + foto; approve Manager → CT berstatus S
⚠ Draft Aktivitas Harian > 7 hari dihapus otomatis setiap kali halaman daftarnya dibuka.
⚠ Lokasi id 2 & 3 (BJI-BBA) di-hardcode pada aturan "Turun Container".

Temuan penting dari bedah kode

KRITIS
Logika approve/reject Administrator salah urutan operator (A || B && C): Admin selalu masuk cabang pertama → BAST ke Vendor APPROVE2 bisa turun lagi ke APPROVE1, reject selalu ke DRAFT. (BAST ke Vendor, BAST dari Vendor, Scrap)
TINGGI
Hak akses bolong: route Lokasi (create/edit/hapus), hapus detail inspeksi, update progress BAST 2 & semua Report tanpa middleware role — semua user login bisa akses.
TINGGI
Scrap APPROVE2 tidak pernah tercapai: route approve hanya untuk Administrator & Manager, cabang Finance tidak bisa dipanggil.
TINGGI
Reject Progress Perbaikan error: typo createdByUser>email (ContainerRepairRepository) → email ke Checker gagal.
SEDANG
dd() tertinggal di Scrap saat email gagal → halaman berhenti, transaksi DB tidak di-commit.
SEDANG
Email praktis sinkron di dalam DB transaction: 15 Mailable pakai ShouldQueue, tapi QUEUE_CONNECTION=sync (.env.example) → SMTP lambat/gagal, POST/approve ikut gagal.
SEDANG
Alamat hardcode: WA gateway 172.16.10.114:3000, 172.16.10.113:8000, email it@baracoal.com, lokasi id 2/3. Dashboard error jika config whatsapp-notif tidak ada.
RENDAH
Seeder akun default memakai password sama Password123 untuk 8 role; sisa boilerplate (OTP, Zenziva, RankUp, Transaction) tidak dipakai.
Langkah cepat tanpa biaya lisensi (hanya jam kerja programmer): perbaiki kondisi approve dengan tanda kurung / cek status terpisah, tambah middleware role di route yang terbuka, hapus dd() & typo, pindahkan IP/email ke .env, kirim email lewat queue setelah commit.
